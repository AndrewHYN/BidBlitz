# Email reliability
The dispatcher uses a single atomic database claim, increasing retry delays, a bounded request timeout, and conditional writes keyed to the current claim attempt. Uncertain deliveries are never automatically replayed after Resend's 24-hour idempotency window. Rate limiting stops the current batch. Optional mail checks current verified recipient and live preferences; private message alerts also recheck chat mute.
Rollout: apply the recorded migration first, then merge after CI. Legacy claims are supported during rollout. The existing daily Vercel sweep remains; this PR does not claim minute-level retries. More frequent authenticated scheduling, webhook-confirmed delivery/bounces and a shared provider quota budget remain separate work. Do not mass retry historical failed jobs. Verify sender domain in Resend; no credentials or DNS changes in this PR.
